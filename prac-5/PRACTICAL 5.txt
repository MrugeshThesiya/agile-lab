5. What is a GitHub Actions Workflow?
A workflow is an automated process that tells GitHub what tasks to perform and when to perform them.
For example:
Whenever new code is pushed to GitHub, automatically run the tests.
A workflow is written using a YAML file.

6. What is YAML?
YAML is a human-readable configuration format.
GitHub Actions uses YAML files to define workflows.
YAML files usually have the extension:
.yml
or:
.yaml
In this practical, our workflow file will be:
go-test.yml

TASK 6: Create math_test.go
Create:
math_test.go
Add:
package main

import "testing"

func TestAdd(t *testing.T) {

    result := Add(5, 3)

    expected := 8

    if result != expected {
        t.Errorf("Expected %d but got %d", expected, result)
    }
}
Why is this file required?
This file contains an automated test for the Add() function.
The test checks:
Actual Result = 8
Expected Result = 8
If both are equal, the test passes.

TASK 16: Create the Workflow File

TASK 17: Write the GitHub Actions Workflow
Open:
go-test.yml
Add:
name: Go CI

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Go
        uses: actions/setup-go@v5
        with:
          go-version: '1.20'

      - name: Download dependencies
        run: go mod download

      - name: Run tests
        run: go test ./...
Save the file.

18. Understand the Workflow
18.1 Workflow Name
name: Go CI
This gives the workflow the name:
Go CI

18.2 Trigger
on:
  push:
This means:
Run the workflow whenever code is pushed to the repository.

18.3 Job
jobs:
  test:
This creates a job called:
test
The job contains the tasks required to test our application.

18.4 Runner
runs-on: ubuntu-latest
This tells GitHub to run the job on a GitHub-hosted Ubuntu environment.
The runner is the computer/environment that executes the workflow.

19. Understand the Steps
Step 1 - Checkout Code
- name: Checkout code
  uses: actions/checkout@v4
Purpose
Gets the project code from the GitHub repository and makes it available to the runner.

Step 2 - Set Up Go
- name: Set up Go
  uses: actions/setup-go@v5
  with:
    go-version: '1.20'
Purpose
Sets up the Go environment required to execute the Go application and tests.

Step 3 - Download Dependencies
- name: Download dependencies
  run: go mod download
Purpose
Downloads the dependencies specified by the Go module.

Step 4 - Run Tests
- name: Run tests
  run: go test ./...
Purpose
Executes the Go test cases automatically.

20. Difference Between uses and run
This is an important concept.
uses
uses: actions/checkout@v4
Means:
Use an existing GitHub Action.
run
run: go test ./...
Means:
Execute a command on the runner.
Therefore:
uses ? Use an existing action

run ? Execute a command

24. Local Execution vs GitHub Actions
It is important to understand that Go can be executed in two places.
On your computer
You manually execute:
go run main.go
and:
go test ./...
Purpose:
Test the application locally.
On GitHub Actions
GitHub automatically executes:
go test ./...
according to the YAML workflow.
Purpose:
Automatically test the application after a code change is pushed.
